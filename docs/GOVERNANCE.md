# 治理文档维护规则

## 目标

治理文档应让执行者快速得到正确约束，而非成为每轮都要吞入的项目历史。以单一事实源、按需加载、可验证预算为准。

## 事实源与职责

| 事实 | 唯一权威位置 | 不应出现的位置 |
| --- | --- | --- |
| AI 入口、硬边界、读取路由 | `AGENTS.md` | 工具摘要文件 |
| 当前阶段、阻断、前三优先级、最后验证 | `CONTEXT.md` | changelog、命令手册、完整债务清单 |
| 可复发经验 | `docs/lessons/*.md` | `CONTEXT.md`、技术债历史 |
| 活跃技术债 | `docs/TECH_DEBT.md` | 状态卡中的重复描述 |
| 阶段规划 | `docs/ROADMAP.md` | 状态卡中的展开计划 |
| 审查、验证、提交规则 | `docs/AI_RULES.md` | `AGENTS.md`、`CONTRIBUTING.md` 的副本 |
| 历史状态、已偿债、长复盘 | `docs/archive/` 与 Git 历史 | 强制加载文件 |

## 强制加载预算

以下上限由 `npm run docs:governance:check` 检查；行数和字符数任一超限都必须先拆分或归档。

| 文件 | 最大行数 | 最大字符数 | 允许内容 |
| --- | ---: | ---: | --- |
| `AGENTS.md` | 85 | 4,500 | 路由、硬约束、工作流入口 |
| `CONTEXT.md` | 45 | 2,600 | 当前决策与三项优先级 |
| `LESSONS.md` | 20 | 1,800 | 任务标签到详情的路由 |
| `CLAUDE.md` / `.cursorrules` | 20 | 1,000 | 指向 `AGENTS.md` 的摘要 |

## 更新规则

1. 先判断事实属于哪个权威文档；只改这一处，再补链接，不复制全文。
2. `CONTEXT.md` 只在阶段、阻断、前三优先级或最后验证结果变化时更新；运行时分支、逐提交记录和完成事项不写入。
3. 当前状态超过三项优先级、技术债超过一句摘要或需要保留时间线时，转为链接到 `TECH_DEBT`、`ROADMAP` 或按日期归档。
4. 已偿债、已完成验收和逐次变更记录移入 `docs/archive/`；活跃文档只保留可行动的事实。
5. 规则需要第二次解释时，抽到其专门文档；入口仅保留一句规则和链接。工具摘要不得新增独立规则。
6. 新增 lesson 只记录可复发且会改变行动的结论；单次事件、实现细节和完整复盘不进入 lesson。

## 变更验收

治理文档改动后必须运行 `npm run docs:governance:check`，并人工确认：链接仍指向权威文档、没有状态副本、`CONTEXT` 的三项优先级仍可执行。源码改动仍按 `AI_RULES` 完成完整 `npm run verify`。
